COMPONENT BREAKDOWN:
─────────────────────────────────────────────────────────────────────────────

┌─ 1. BASE SYSTEM PROMPT
│  ├─ Source: Profile settings
│  ├─ Example: "You are a helpful coding assistant"
│  ├─ Size: 200-500 tokens
│  └─ Status: ✅ Always there, never changes
│
├─ 2. PREVIOUS SESSION SUMMARY  
│  ├─ Source: Last session's closeout
│  ├─ Contains: Last ~6 messages summarized
│  ├─ Size: 200-500 tokens
│  └─ Status: 🟡 Empty if first session
│
├─ 3. LONG-TERM MEMORY NOTES
│  ├─ Source: Extracted from all previous chats
│  ├─ Selection: Vector-ranked by relevance
│  ├─ Size: 0-1500 tokens (token budget)
│  ├─ Categories: fact, progress, blocker, action_item, other
│  ├─ Format: "- [category] content text"
│  └─ Status: 🟢 Always included (can be empty)
│
└─ 4. CONVERSATION HISTORY
   ├─ Source: In-memory array (grows each turn)
   ├─ Initial: Last 20 messages from previous session
   ├─ Growth: +2 per turn (user + assistant)
   ├─ Current turn: Latest user message with datetime injected
   └─ Status: 🟢 Always included, unbounded growth

HOW MEMORY NOTES ARE SELECTED:
─────────────────────────────────────────────────────────────────────────────

Step 1: VECTOR RANKING
  Input: System prompt + session summary
  Process: Embed → Vector search in note store → Find top 6 most similar
  Output: Ranked note IDs by similarity

Step 2: IMPORTANCE REORDERING  
  Input: Ranked notes from step 1
  Process: Sort by importance score (1-10) then by recency
  Output: Reordered note list

Step 3: TOKEN BUDGETING
  Input: Reordered notes + budget (default: 1500 tokens)
  Process: Add notes until budget exhausted
  Output: Selected notes (subset)

Example:
  Budget: 1500 tokens
  
  Selected:
  ✓ Note A: [fact] Python uses FastAPI (100 tokens) → total: 100
  ✓ Note B: [fact] PostgreSQL with Alembic (120 tokens) → total: 220
  ✓ Note C: [progress] Auth 70% complete (150 tokens) → total: 370
  ✓ Note D: [blocker] OAuth2 pending (110 tokens) → total: 480
  ✓ Note E: [action_item] Meet with security (85 tokens) → total: 565
  ✓ Note F: [fact] Deployment uses Docker (95 tokens) → total: 660
  
  Cannot add more notes (next would exceed 1500 token budget)

WHAT GETS CACHED:
─────────────────────────────────────────────────────────────────────────────

Cached: The ENTIRE assembled context
├─ Base prompt
├─ Session summary  
├─ Memory notes (formatted)
└─ All three combined

Cache Key Based On:
  hash(
    profileID,           ← Which profile
    systemPrompt,        ← What instructions
    notesHash,           ← Which notes selected (our fix!)
    tokenBudget          ← How many tokens available
  )

Cache Duration: 30 days
Cache Hit When: Same notes selected (most of the time)
Cache Miss When: New notes extracted or system prompt changes

CACHE INVALIDATION TRIGGERS:
─────────────────────────────────────────────────────────────────────────────

✅ Cache HIT (context reused):
   └─ Same notes selected on app open

❌ Cache MISS (context rebuilt):
   ├─ New notes extracted in previous session
   ├─ System prompt changed
   ├─ Token budget changed
   ├─ Different embedding model selected
   └─ Profile deleted/recreated
